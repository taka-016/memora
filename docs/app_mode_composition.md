# アプリモードと依存構成

## 基本方針

- ビルド指定から起動時に一度だけ`AppMode`を決め、認証、保存先、外部サービス、Androidウィジェットまで同じモードで実装を選ぶ。`auto`と未指定はオンラインとして扱う。
- オンラインはFirestoreとFirebase認証を使用する。オフラインは端末内の利用者と[SQLite](offline_database.md)を使用し、認証を要求しない。両モードのデータ共有・同期・移行は行わない。
- モードごとの具体的な実装の選択・初期化・注入はComposition Rootに集める。Application層のUseCaseはインターフェースを受け取り、Presentation層はモード判定や保存先の選択を行わない。
- オフラインではFirebase、Crashlytics、NTPなどのオンライン用SDKを初期化せず、外部通信を行わない。地図・場所・現在地・共有・招待・アカウント操作は利用不可とし、入口と直接遷移の両方で制限する。

## プラットフォーム上の注意

- Firebaseの自動初期化・自動収集は無効にし、オンラインでだけ明示的に有効化する。Apple向けに`GoogleService-Info.plist`を追加すると、FlutterFireがプラグイン登録時にFirebaseを初期化し得るため、オフライン起動の条件を再検証する。
- Androidウィジェットは保存済みの解決済みモードと現ビルドのモードが一致する場合だけ更新する。不明・未保存・不一致なら更新依存を初期化せず、旧モードのキャッシュも表示しない。ネットワーク接続を更新条件にするのはオンラインだけとする。
- ウィジェットキャッシュは再生成できる派生データとして扱う。オフラインでは1回の生成で旅行と旅程を同じDBスナップショットから取得する。取得失敗を空結果と区別して既存表示を維持する。同じ対象への更新が重なった場合の厳密な順序は保証せず、一時的に古い表示になっても保存後・手動・定期更新で復旧する。厳密な順序が必要になった場合は更新要求の直列化を検討する。
