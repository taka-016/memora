# ADR-011: 親子の編集は集約単位で競合を検出し原子的に保存する

## ステータス

採用

## 決定日

2026-10-15

## コンテキスト

親子の全件置換や子だけの変更を扱う保存処理がある。

## 検討した選択肢

| 選択肢 | 判断 |
| --- | --- |
| 親のバージョンで競合を検出し、親子を原子的に保存する | 採用 |
| 親子・子の変更を別々に競合管理する | 不採用 |
| DVC契約一覧をグループのバージョンで排他する | 撤回 |
| DVC契約一覧に専用の親ドキュメントを追加する | 一度採用後、撤回 |
| DVCは各契約自身をポイント利用・期間限定ポイントの親とする | 現在の採用案 |

## 決定事項

- 旅行と場所・タスク・旅程、グループと所属メンバー、予定と個別回は、それぞれ旅行・グループ・予定を集約の親とする。
- DVCは各契約をポイント利用・期間限定ポイントの親とし、グループや契約一覧全体とは独立した競合単位とする。
- 子だけの変更も親のバージョンで排他し、親子の変更を原子的に保存する。競合時は集約全体の変更を拒否する。

## 決定理由

- 親子の全件置換や子だけの変更が別々に競合管理されると、古い編集内容で他の人が変更した子を削除・上書きする可能性があるため、親のバージョンで集約単位の競合を検出する。
- 保存の途中失敗で一部だけが更新されることを避けるため、親子を原子的に保存する。

## 結果

- 同じ集約に属する異なる子の編集でも競合し、再読み込みが必要になる場合がある。
- グループ編集とDVC契約編集は別の競合単位となる。
- 集約全体を原子的に保存する必要があり、Security Rulesの親参照による読み取り課金と回数制限を考慮する必要がある。
