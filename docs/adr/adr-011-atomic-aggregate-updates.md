# ADR-011: 親子の編集は集約単位で競合を検出し原子的に保存する

## ステータス

採用

## 決定日

DVCを各契約自身で排他する現行方針は、2026-10-15（日本時間）の[変更コミット](https://github.com/taka-016/memora/commit/2d6b9e9742033835ce9238dce3e0ddec549ac891)で記録されている。

## コンテキスト

親子の全件置換や子だけの変更を扱う保存処理がある。

## 検討した選択肢

既存ADR・関連PR・変更履歴で確認できる選択肢を示す。

| 選択肢 | 判断 |
| --- | --- |
| 親のバージョンで競合を検出し、親子を原子的に保存する | 採用 |
| 親子・子の変更を別々に競合管理する | 不採用 |
| DVC契約一覧をグループのバージョンで排他する | 撤回 |
| DVC契約一覧に専用の親ドキュメントを追加する | 一度採用後、撤回 |
| DVCは各契約自身をポイント利用・期間限定ポイントの親とする | 現在の採用案 |

DVC専用親への変更は[2026-10-13の記録](https://github.com/taka-016/memora/commit/e0714cc273db4eef4e70bab7e00bfa72f52a84dd)、各契約を親にする変更は[2026-10-15の記録](https://github.com/taka-016/memora/commit/2d6b9e9742033835ce9238dce3e0ddec549ac891)を参照。

## 決定事項

- 旅行と場所・タスク・旅程は旅行、グループと所属メンバーはグループ、予定と個別回は予定を親とし、それぞれの親のバージョンで排他する。DVCは各契約自身をポイント利用・期間限定ポイントの親とし、契約のバージョンで排他する。契約一覧用の専用親は作らず、グループのバージョンとは独立して排他する。子だけの追加・変更・削除でも親を同じ原子的な処理で更新する。
- 親の競合時は親子の保存全体を拒否する。既存のバッチ・トランザクションを利用し、順次保存している経路は排他に必要な範囲で原子的な処理へまとめる。DVCは契約IDを維持して保存し、契約と利用データの親子関係の仕様修正を排他導入より先に行う。グループのバージョンはグループ自身と所属メンバーの編集に使用し、DVC契約編集では更新しない。
- 親子の置換を伴わない更新は既存の編集対象ドキュメントのバージョンで排他する。削除のみの対象にも期待バージョンを保持し、削除時の排他はADR-012に従う。

## 決定理由

- 親子の全件置換や子だけの変更が別々に競合管理されると、古い編集内容で他の人が変更した子を削除・上書きする可能性があるため、親のバージョンで集約単位の競合を検出する。
- 保存の途中失敗で一部だけが更新されることを避けるため、親子を原子的に保存する。
- DVCのポイント利用・期間限定ポイントは各契約に紐付くため、契約自身を親とし、グループ編集との競合単位を分ける。

確認資料: [PR #491](https://github.com/taka-016/memora/pull/491)、[PR #492](https://github.com/taka-016/memora/pull/492)。

## 結果

異なる子の編集でも競合し、再読み込みが必要になる場合がある。グループ編集とDVC契約編集はグループと契約それぞれのバージョンで管理し、互いの更新による競合を起こさない。DVCでは契約と利用データの紐付け、および契約全削除・再作成の保存方法の修正が必要になる。親の参照によるRulesの読み取り課金と回数制限を考慮して、集約全体を原子的に保存する必要がある。
