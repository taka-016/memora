# ADR-010: オンラインの更新排他は整数バージョンとSecurity Rulesで行う

## ステータス

採用

## 決定日

2026-10-13

## コンテキスト

オンラインモードでは、複数端末の編集やキャッシュから取得した内容の保存を扱う。

## 検討した選択肢

| 選択肢 | 判断 |
| --- | --- |
| 編集開始時の整数バージョンを保持し、Rulesで更新を検証する | 採用 |
| バージョンを自動加算する、または保存直前の最新版へ期待値を差し替える | 不採用 |

## 決定事項

- 最小限の改修を前提とし、既存の取得・全件置換・保存フロー・トランザクションをできるだけ維持する。変更はバージョンの導入と、単一ドキュメントまたは親のバージョンによる更新・削除の排他に必要な範囲に限定する。
- 作成時の整数`version`は1とし、取得結果から編集状態・保存要求まで編集開始時の値を保持する。更新時はその値に1を足した固定値を送る。
- Security Rulesで更新後の整数バージョンがサーバーの現在値より1大きい場合だけ対象更新を許可する。現行の認証条件を維持し、包括的な許可で検証を迂回できない構成にする。
- 自動加算や保存直前の最新版への期待バージョンの差し替えは行わない。既存トランザクションの自動再試行でも編集開始時の期待値を照合する。
- 既存データのバージョンは導入時に初期化する。利用対象は現行アプリとし、旧アプリとの互換処理や旧アプリ専用のアクセス遮断・削除プロトコルは追加しない。
- 更新が拒否された場合は既存の失敗処理を利用し、入力を残して編集し直せるようにする。必要な修正はこの範囲に限定し、拒否原因を特定するための追加取得は行わない。

## 決定理由

- 複数端末の編集や古いキャッシュからの保存で、他の人の変更を上書きする可能性があるため、取得時のバージョンに基づく排他を行う。
- 保存直前の最新版を使ってバージョンを更新すると古い編集内容の競合を検出できないため、編集開始時の期待値を保存と再試行まで維持する。

## 結果

同じバージョンからの更新は一方だけが成功する。取得結果と保存要求へのバージョンの追加、Rulesの変更、既存データの初期化が必要になる。
