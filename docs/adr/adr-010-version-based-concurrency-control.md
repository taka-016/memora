# ADR-010: オンラインの更新・削除は整数バージョンで楽観的排他を行う

## ステータス

採用

## 決定日

2026-10-13

## コンテキスト

オンラインモードでは、複数端末の編集やキャッシュから取得した内容の更新・削除を扱う。

## 検討した選択肢

| 選択肢 | 判断 |
| --- | --- |
| 更新・削除とも取得時の整数バージョンで競合を検出する | 採用 |
| バージョンを自動加算する、または保存直前の最新版へ期待値を差し替える | 不採用 |
| 独立した物理削除には期待バージョン照合を追加しない | 不採用 |

## 決定事項

- オンラインの更新・削除は、編集開始時の整数バージョンを期待値とする楽観的排他で制御する。
- 削除・退避は現在のバージョンが期待値と一致する場合だけ許可し、取得後に変更された対象のデータを失わないようにする。
- Security Rulesで、更新後のバージョンがサーバーの現在値より1大きい場合だけ更新を許可する。
- 自動加算や保存直前の最新版への期待値の差し替えは行わず、再試行でも編集開始時の期待値を維持する。

## 決定理由

- 複数端末の編集や古いキャッシュからの保存で、他の人の変更を上書きする可能性があるため、取得時のバージョンに基づく排他を行う。
- 保存直前の最新版を使ってバージョンを更新すると古い編集内容の競合を検出できないため、編集開始時の期待値を保存と再試行まで維持する。
- 更新だけを排他しても、古い画面からの削除で他の人が更新したデータを失う可能性があるため、削除にも期待バージョンの照合を適用する。

## 結果

同じバージョンからの更新は一方だけが成功する。取得後に変更された対象の削除・退避も拒否される。取得結果と保存要求へのバージョンの追加、Security Rulesの検証、既存データへのバージョン設定が必要になる。
