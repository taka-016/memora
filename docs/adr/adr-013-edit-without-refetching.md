# ADR-013: 通常の取得結果で編集し確認用の再取得を追加しない

## ステータス

採用

## 決定日

不明

## コンテキスト

オンラインモードでは、永続キャッシュを利用して取得した内容から編集したい。

## 検討した選択肢

| 選択肢 | 判断 |
| --- | --- |
| 通常の取得結果と取得時のバージョンを編集に使う | 採用 |
| 編集開始時・保存前の確認用再取得や親バージョンの前後照合を追加する | 不採用 |
| 子の完全な一覧と削除IDを編集状態で保持し、保存時の一覧取得をなくす | 当初案を撤回。既存の保存に必要な取得を維持 |

## 決定事項

- オンラインモードの閲覧・編集には通常の取得結果を利用し、キャッシュから得た内容とバージョンによる編集も許可する。編集開始時のサーバー再取得や親バージョンの前後照合を追加しない。通信断で親はサーバーの最新版、子は古いキャッシュから取得されるケースは稀として許容し、専用の混在検出・再取得は追加しない。
- 保存前の競合確認・保存完了確認のための再取得は追加しない。編集開始時のバージョンを保持し、保存時にRulesまたは既存トランザクション内で照合する。既存トランザクションの必要な読み取りは維持する。削除時の排他に必要なトランザクション内の取得はADR-012に従って行う。
- 既存の全件置換・削除処理と、その書き込み対象を決めるための取得は維持する。
- 保存状態と対象更新経路の排他制御を導入・検証してから永続キャッシュを有効化し、容量はSDKの既定値を使用する。通常の`get()`はサーバーから取得を試み、接続できない場合にキャッシュを利用する扱いを維持し、キャッシュ優先の独自取得方針は追加しない。

## 決定理由

- 編集開始時の最新化や保存前の確認のために再取得を追加すると、通信と実装が増え、キャッシュを利用する編集にも制約が生じるため、通常の取得結果を利用する。
- 通信断時にサーバーの最新の親と古いキャッシュの子が混在するケースは稀として許容する判断であるため、専用の混在検出・再取得は追加しない。
- 既存の保存処理で書き込み対象を決めるために必要な取得は維持し、確認だけを目的とした追加通信を避ける。

## 結果

確認用の通信を増やさず、期待バージョンが古い更新は保存時に拒否する。通信断時に親と子の取得時点が混在した保存までは検出しない。既存の保存処理で必要な取得は維持する。キャッシュ有効化だけで通常取得のサーバー通信が省かれるわけではない。
