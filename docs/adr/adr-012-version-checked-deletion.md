# ADR-012: オンラインの削除も期待バージョンを照合してから行う

## ステータス

採用

## 決定日

不明

## コンテキスト

オンラインモードでは、画面などで取得した対象を後から削除する。通常の`delete()`には期待バージョンを渡せない。

## 検討した選択肢

| 選択肢 | 判断 |
| --- | --- |
| 取得時の期待バージョンをトランザクションで照合して削除する | 採用 |
| 独立した物理削除には期待バージョン照合を追加しない | 当初案を撤回 |

## 決定事項

- オンラインの削除要求にも画面などで取得した期待バージョンを渡し、現在値と一致する場合だけ削除する。保存直前の最新版へ期待値を差し替えない。
- 親が残る子の削除は、親のバージョン更新と同じバッチ・トランザクションで行い、親の期待バージョンで排他する。
- 親自身・単独ドキュメントの削除はトランザクションで現在値を読み、期待バージョンと一致するときだけ削除する。既存トランザクションはそのまま利用し、再試行でも同じ期待値で照合する。親と子をまとめて削除する場合も、親の照合と削除を同じトランザクションで行う。
- グループ・メンバーの退避、メンバーイベントの空メモによる削除、招待承認後の招待削除にも照合を適用する。既存の削除制約と関連データの更新処理は維持する。
- 親削除後に表示・操作に影響しない子が残ることの許容は維持し、残存防止のための一覧の強制サーバー取得や追加対策は行わない。

## 決定理由

- 更新だけを排他しても、古い画面からの削除で他の人が更新したデータを失う可能性があるため、削除にも取得時の期待バージョンを適用する。
- 通常の`delete()`に期待バージョンを渡せなくても、トランザクション内で取得時の期待値と現在値を照合してから削除できるため、既存トランザクションを利用し、必要な経路だけ追加する。

## 結果

取得後に変更された対象は削除せず、既存の失敗処理で扱う。通常の削除からトランザクションへ変更する経路では読み取りが必要で、通信断では削除を実行できない。削除の排他に必要な取得・トランザクションだけを追加する。
