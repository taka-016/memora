# ADR-005: 業務データの登録はアプリ経由のみを前提とする

## ステータス

採用

## 決定日

未確認。採用方針としてADRへ記録された日は2026-10-04（日本時間、[記録コミット](https://github.com/taka-016/memora/commit/4d64ddc8098d7c8b9ab4fce92822a2b4f72abf53)）。実際の合意日を示す記録は確認できない。

## コンテキスト

業務データはアプリの登録処理でドメインルールを検証して保存する。

## 検討した選択肢

既存ADR・関連PR・変更履歴で確認できる選択肢を示す。

| 選択肢 | 判断 |
| --- | --- |
| アプリ経由の登録とドメイン検証を前提にする | 採用 |
| 外部直接登録の不正データも想定し、読取隔離・専用テスト・削除スクリプトを用意する | 不採用。PR #485で関連対応を撤回 |

## 決定事項

今後も、オンライン・オフラインを問わず業務データの登録はアプリ経由のみを前提とする。Firestore APIや管理コンソールなど、アプリを通さない直接登録は対応範囲に含めず、その経路の不正データを想定した隔離処理、専用テスト、削除スクリプトは追加しない。

## 決定理由

外部からDBへ直接登録された不正データを想定すると、現行の利用経路にない隔離・復旧処理が必要になり、実装と運用が複雑になるため。アプリの登録時のドメイン検証を前提に対応範囲を限定する。

確認資料: [PR #485](https://github.com/taka-016/memora/pull/485)。

## 結果

登録時のドメイン検証で整合性を保つ。外部からの直接登録への対応が必要になった場合は、この前提を明示的に見直してから実装する。
