# ADR-006: 予定のタイムゾーンをデータに保持し画面入力を求めない

## ステータス

採用

## 決定日

2026-10-05

## コンテキスト

アプリは日本国内での利用を対象とする。予定の繰り返し時刻を解釈するにはタイムゾーンが必要になる。

## 検討した選択肢

| 選択肢 | 判断 |
| --- | --- |
| 日本時間を内部設定し、タイムゾーンをデータに保持する | 採用 |
| 利用者が画面でIANAタイムゾーンIDを入力する | 不採用。入力欄を削除 |

## 決定事項

- 予定の登録・編集画面にはタイムゾーンの入力欄を設けない。
- 時刻付きの繰り返し予定は、タイムゾーンをデータの`timeZone`に保持する。新規設定時は日本時間の`Asia/Tokyo`を内部で設定し、編集時は保存済みの値を引き継ぐ。
- 単発予定と終日予定のタイムゾーンの扱いは既存のデータモデルに従う。

## 決定理由

日本国内での利用を対象とするため、利用者にIANAタイムゾーンIDの入力を求める必要はない。一方、繰り返し時刻の解釈にはタイムゾーンが必要であるため、入力欄を設けずデータとして保持する。

## 結果

利用者は地域の識別名を入力せずに予定を設定できる。繰り返し日時の解釈に必要なタイムゾーンは、オンライン・オフラインともデータとして維持する。
