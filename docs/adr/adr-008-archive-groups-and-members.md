# ADR-008: グループとメンバーは削除済み保存先へ移動し関連データを残す

## ステータス

採用

## 決定日

不明

## コンテキスト

グループとメンバーの削除は、配下の記録や所属関係にも関係する。復活機能そのものは今回の要求に含めない。

## 検討した選択肢

| 選択肢 | 判断 |
| --- | --- |
| 別の保存先へグループ・メンバーを退避し、関連データを残す | 採用 |
| 通常テーブルに行を残したまま非表示にする | 不採用 |
| グループ・メンバーと関連データを削除する | 退避方式へ変更 |

## 決定事項

- オンライン・オフラインの双方で、削除時のグループ・メンバーの情報を元のIDとともに削除済み保存先へ移す。Firestoreでは専用コレクション、SQLiteでは専用テーブルを用意する。
- 退避先への保存と元の`groups`・`members`からの削除を原子的に行う。通常のグループ・メンバーテーブルに行を残して非表示にする方式は採用しない。退避に失敗した場合は元のデータを失わないようにする。オンラインの退避でも取得時の期待バージョンを照合し、変更済みなら退避と元データの削除を行わない。
- 退避処理では、グループの旅行・予定・ラベル・DVCデータ・所属、メンバーの所属・イベント・タスク担当などの関連データは削除せず、元のIDとの関係を残す。SQLiteでも通常テーブルの親を削除することで連鎖削除や担当の解除が起きない参照構造へ変更する。グループ退避と重なる関連データの書き込み通過は、旅行・場所・タスク・旅程、予定・個別回・ラベル、イベント、DVC、所属などすべて許容し、退避前に開いた画面からの保存も拒否しない。この競合の拒否を目的とするグループ存在確認・退避状態照合・関連データの一括バージョン更新・追加Rules・専用テストは追加しない。各編集対象の期待バージョンによる排他は維持する。
- 元のグループ・メンバーが通常テーブルからなくなるため、通常の取得・一覧・選択・操作では削除済みとして扱う。残した関連データがあることを理由に、退避したグループやメンバーを通常画面やAndroidウィジェットへ表示しない。
- 復活機能は作らず、退避したデータの保持を目的とする。オフラインの退避テーブルはSQLiteの正本として通常のバックアップ・復元対象に含め、関連データと同じ時点の内容を保存・復元する。
- Firebase Authenticationのアカウント削除や旅行・予定などの個別削除は、この判断によって変更しない。

## 決定理由

- グループとメンバーを誤って削除すると、配下の記録や所属関係まで失う影響が大きいため、将来必要になったときに復活させられるよう、まずデータが残っていることを重視する。
- 退避先への保存失敗で元のデータを失わないよう、退避先への保存と元データの削除を原子的に行う。
- 今回の目的はデータの保持であり、復活機能そのものは要求に含まれないため、復活機能は作らない。

## 結果

- 誤削除後も親の情報と関連データが残り、将来復活が必要になった際に利用できる。ただし、グループ退避の時点で関連データを凍結する保証はなく、並行する保存によって退避後に関連データが変更されることは許容する。退避後の通常画面・ウィジェットからの表示・選択・操作の除外は維持し、アプリから復活させる機能は提供しない。
- 退避した情報と関連データは保存容量を消費し続ける。通常テーブルからの削除と関連データの保持を両立するため、SQLiteの参照制約と関連データの取得経路を調整する必要がある。
- ADR-007で扱っていたグループ削除後のデータは、復活の可能性に備えて保持する対象とする。
