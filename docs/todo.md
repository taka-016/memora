# ToDo List

## オフライン版・オンライン版の別アプリ対応

### 1. 別アプリとしての仕様をユーザーストーリーへ反映する

- オンライン版は現在のFirebase Auth、Firestore、地図、共有、招待機能を維持する
- オフライン版はユーザー登録やログインを不要とし、Android内部SQLite DBだけで業務データを管理する
- オフライン版では地図、共有、招待などのオンライン機能を利用できない
- オンライン版とオフライン版は異なるAndroid application IDを持つ別アプリとし、同じ端末へ同時にインストールできるようにする
- 2つのアプリはAndroidの内部ストレージを共有せず、それぞれ独立したデータを保持する
- アプリ内でオンライン版とオフライン版を切り替える機能は作成しない
- SQLiteとFirestoreの間でデータを同期・移行する機能は今回作成しない
- 有料化、Google Play Billing、オンライン利用権、無償オンライン利用の手動付与は今回の対応範囲から外す
- 実装着手前にユーザーストーリーの内容をレビューし、今回の対応範囲を確定する

### 2. オンライン版とオフライン版のリリースビルドを分ける

- Context7で公式ドキュメントを確認してから、Flutter FlavorとAndroid Product Flavorの構成を決める
- オンライン版とオフライン版で異なるAndroid application IDを設定する
- オンライン版とオフライン版を端末上で判別できるアプリ名とアイコンを設定する
- ビルド時にアプリ種別を確定し、実行中に変更されない構成にする
- オンライン版とオフライン版で別のエントリーポイントまたはComposition Rootを使用する
- オンライン版では既存のFirebase設定と`MAPS_API_KEY`を使用する
- オフライン版にはFirebase設定と`MAPS_API_KEY`を埋め込まず、Firebaseと地図SDKを初期化しない
- オフライン版から不要なFirebase・地図関連SDKを除外できる構成を検討し、少なくとも外部サービスへの通信が発生しないことを保証する
- オンライン版とオフライン版のバージョン番号、署名、配布、更新方針を決める
- ストアへ公開する場合は、Google Play Consoleで別アプリとして登録する
- release APK作成スクリプトから、オンライン版とオフライン版を区別できるファイル名でそれぞれ出力する
- CIでオンライン版とオフライン版の両方をビルドできるようにする

### 3. 外部サービスへの依存をInfrastructure層へ集約する

- Firebase、Firestore、Crashlytics、NTP、Places SDK、ネットワーク状態取得の具象型を使用している箇所を洗い出す
- Application層とCore層には外部サービスを抽象化したインターフェースだけを配置し、具象実装をInfrastructure層へ配置する
- `main.dart`から個別SDKの初期化処理を除き、各リリースビルドのComposition Rootから必要なInfrastructure実装だけを初期化する
- Androidウィジェットのバックグラウンド更新と操作コールバックからFirestore具象実装への直接依存を除く
- ロガーからCrashlyticsへの直接依存を除き、オンライン版はCrashlytics、オフライン版は端末内またはno-opの実装を構成する
- アプリ時刻からNTPへの直接依存を除き、オンライン版はNTP、オフライン版は端末時刻の実装を構成する
- 地図関連サービスの利用可否と利用できない理由を表す状態をApplication層に定義する
- オフライン版では地図関連サービスを常に利用不可とし、オンライン版では既存の利用可否判定を使用する
- Application層とCore層から禁止対象の外部サービスパッケージをimportしていないことをアーキテクチャテストで確認する

### 4. Android内部SQLite DBを構築する

- `group_members`の既存データに保存されている`orderIndex`をER図へ追記する
- `orderIndex`の反映漏れ以外はER図のテーブル、項目、主キー、外部キー、関連を変更しない
- Firestoreの既存Collection・フィールド構造を変更せず、ER図と現在のFirestore Mapperを基準にSQLiteスキーマを定義する
- Context7で公式ドキュメントを確認してからDriftと必要な関連パッケージを追加する
- Android内部ストレージにSQLiteファイルを作成し、DBの初期化、終了、バージョン管理を行う
- Driftのスキーママイグレーション方針を整備する
- 日時、真偽値、nullable項目を既存Entity・DTOと相互変換できる保存形式へ統一する

### 5. SQLite用のデータアクセスを実装する

- メンバー、メンバーイベント、招待のMapper、Repository、QueryServiceを実装する
- グループ、グループメンバー、グループイベントのMapper、Repository、QueryServiceを実装する
- 旅行、訪問場所、タスク、旅程項目のMapper、Repository、QueryServiceを実装する
- DVCポイント契約、期間限定ポイント、利用履歴のMapper、Repository、QueryServiceを実装する
- 複数更新を原子的に保存できるSQLite用`WriteTransaction`を実装する
- 既存の並び替え条件、関連データの組み立て、保存・更新・削除の振る舞いをFirestore実装と一致させる
- Repository、QueryService、TransactionのFactoryからSQLite実装を生成できるようにする

### 6. 各リリースビルドへデータアクセスと利用可能機能を組み込む

- オフライン版のFactoryからSQLiteのRepository、QueryService、Transactionを生成する
- オンライン版のFactoryから既存のFirestore実装を生成する
- オフライン版では認証画面とAuthGuardを経由せずに利用開始する
- オンライン版では既存のFirebase Auth実装を使用する
- オフライン版で現在のメンバー情報が必要な場合は、登録やログインとして扱わない端末内データとして初期化する
- UseCase、Domain Entity、DTOはアプリ種別と具象データソースを意識しない構成を維持する
- オフライン版では地図画面、場所検索、周辺地点検索、現在地を利用する操作を無効化し、利用できないことを案内する
- オフライン版では共有と招待に関する画面・操作を無効化し、利用できないことを案内する
- 保存済みの場所名、座標、旅行・旅程との関連は、地図機能がない場合も文字情報として参照できるようにする
- UI以外から地図、共有、招待のオンラインサービスが呼ばれた場合も、共通の利用不可エラーを返す
- 設定画面でオンライン版またはオフライン版のどちらを使用中か、データ保存先、利用可能機能を確認できるようにする

### 7. Androidウィジェットを両方のリリースビルドへ対応する

- バックグラウンド更新と操作コールバックでも、共通UseCaseをバックグラウンド用Composition Rootから取得する
- オフライン版ではSQLite、オンライン版ではFirestoreのQueryServiceを共通UseCaseへ注入する
- オフライン版では、バックグラウンドisolateからSQLiteを安全に開閉する
- オンライン版だけ定期更新へネットワーク接続条件を設定する
- アプリ内の旅程更新後にウィジェットキャッシュを更新する
- オンライン版とオフライン版でウィジェットの識別子、設定、キャッシュが衝突しないようにする

### 8. オフライン版のデータ保護方針を確定する

- パスポート番号などの機微情報を含むSQLite DBについて暗号化要否と鍵管理方法を決める
- Android Auto Backupと端末間転送へSQLite DBを含めるか、端末外へ出さないかを決める
- アプリ削除、データ消去、端末故障時のデータ消失を案内する
- 暗号化したエクスポート・インポートによる手動バックアップの要否を決める
- 確定した方針に基づき、SQLite DBの暗号化または手動バックアップが必要な場合は実装する

### 9. 両方のリリースビルドを検証して設計資料を更新する

- SQLiteの保存、取得、更新、削除、並び替え、関連データ取得、ロールバック、DB再オープンをテストする
- Driftのスキーママイグレーションをテストする
- オフライン版で新規起動・再起動し、全業務データをSQLiteだけで操作できることを確認する
- オフライン版でFirebase、Firestore、Crashlytics、NTP、Places SDK、地図SDKが初期化されず、外部サービスへ通信しないことを確認する
- オフライン版で地図、共有、招待の全操作が同じ基準で無効化されることを確認する
- オンライン版で既存のFirestore保存、認証、共有、招待、地図機能が維持されることを確認する
- Androidウィジェットについてオンライン版、オフライン版、端末再起動後、アプリ未起動をテストする
- オンライン版とオフライン版を同じ端末へ同時にインストールし、アプリ、DB、設定、ウィジェットが干渉しないことを確認する
- release APK作成スクリプトとCIから両方のリリースビルドを作成できることを確認する
- 確定したユーザーストーリーを基準に、別アプリ構成、データ保存先、利用可能機能をユースケース図へ反映する
- ER図、Firebase設定、環境設定、ビルド・配布手順を実装結果と一致させる

## マップの表示

- 地図画面上で表示対象グループを切り替えられるようにする
  - ドロワーから地図を選択したときは、年表と同じように所属グループを読み込む
  - 所属グループが2件以上の場合はグループ選択画面を表示し、1件の場合は選択画面を省略してそのグループの地図を表示する
  - グループ選択画面で所属グループを1つ選ぶと、そのグループを表示対象として地図画面へ遷移する
  - グループの読み込み中、所属グループがない場合、読み込みに失敗した場合は、既存のグループ選択画面と同じ表示と再読み込み動線を使用する
  - 場所検索ボックスの直下左側に、選択中のグループ名と下向き矢印を表示したコンパクトなチップを置く
  - チップをタップすると、所属グループから表示対象を1つ選べるポップアップメニューを表示する
  - グループを選択すると、そのグループに属する場所のピンと、ピン詳細に表示する旅行だけに絞り込む
  - 表示対象の切り替え時に開いていたピン詳細を閉じ、選択後のピンだけを移動対象にする
  - 場所検索は表示対象グループによる絞り込みの対象外とし、選択中のグループにかかわらず利用できるようにする
  - グループ名が長い場合はチップの最大幅を制限し、省略記号付きで表示する
  - 選択したグループに場所がない場合も地図とグループ選択は操作可能な状態を保ち、ピンがないことを案内する
  - 所属グループが1件の場合の選択省略、2件以上の場合のグループ選択、選択後の地図表示、地図上での別グループへの切り替え、場所がないグループの表示をWidgetテストで確認する
