# ToDo List

## 無料オフライン・オンライン対応

- 1. 無料オフラインモードとオンラインモードの仕様をユーザーストーリーへ反映する
  - 無料オフラインモードではユーザー登録やログインを行わずにアプリを利用開始できることを明記する
  - 無料オフラインモードではデータをSQLiteだけに保存し、地図、共有、招待などのオンライン機能を利用できないことを明記する
  - オンラインモードではFirebase Authへ新規登録またはログインし、Firestore、地図、共有、招待などのオンライン機能を利用できることを明記する
  - 有効なストア契約または運営付与がある場合にオンラインモードを利用できることを明記する
  - 運営付与の対象者は、支払いを行わずにオンラインモードの全機能を利用できることを明記する
  - ストア契約と運営付与のいずれのオンライン利用権も確認できない場合は、無料オフラインモードとして利用することを明記する
  - SQLiteとFirestoreのデータ同期は設定画面から手動実行し、自動同期や自動マージを行わないことを明記する
  - オンラインから無料へ変更する場合は事前のデータ同期を警告するが、同期を強制しないことを明記する
  - 実装着手前にユーザーストーリーの内容をレビューし、無料オフラインモードとオンラインモードの前提を確定する

- 2. 外部サービスへの依存をInfrastructure層へ集約する
  - Firebase、Firestore、Crashlytics、NTP、Places SDK、ネットワーク状態取得の具象型を使用している箇所を洗い出す
  - Application層とCore層には外部サービスを抽象化したインターフェースだけを配置し、具象実装をInfrastructure層へ配置する
  - `main.dart`から個別SDKの初期化処理を除き、選択中の利用モードに応じたInfrastructure層の初期化処理を呼び出す構成にする
  - Androidウィジェットのバックグラウンド更新と操作コールバックからFirestore具象実装への直接依存を除く
  - ロガーからCrashlyticsへの直接依存を除き、ログ出力先をInfrastructure層で構成する
  - アプリ時刻からNTPへの直接依存を除き、利用モードに応じた時刻実装をInfrastructure層で構成する
  - Application層とCore層から禁止対象の外部サービスパッケージをimportしていないことをアーキテクチャテストで確認する

- 3. 無料オフラインモードとオンラインモードを定義する
  - 無料オフラインモードではユーザー登録やログインを不要とし、Android内部SQLite DBを使用する
  - オンラインモードではFirebase Authへの新規登録またはログインを必要とし、Firestoreを使用する
  - ネットワーク接続状態ではなく、有効なストア契約または運営付与の有無から利用モードを決定する
  - オンライン利用権と取得元を表すモデルをApplication層に定義し、ストア契約と運営付与の判定結果を統一して扱う
  - ストアの購入・契約状態を取得するインターフェースをApplication層に定義し、ストアSDKの具象実装をInfrastructure層へ配置する
  - ストア契約と運営付与のどちらか一方を有効と確認できた場合はオンラインモードを使用する
  - どちらのオンライン利用権も有効と確認できない場合は、前回確認した状態を使用せず無料オフラインモードとして起動する
  - 開発用の設定ではストア契約や運営付与に依存せず、無料オフラインモードとオンラインモードを切り替えられるようにする
  - 開発用の利用モード切替がリリースビルドでは使用できないことを保証する
  - 選択中の利用モードをアプリ起動、バックグラウンド処理、各Factoryで一貫して参照できるようにする
  - 利用中のモード、オンライン利用権の取得元、データ保存先、利用できる機能を設定画面で確認できるようにする
  - 無料、ストア契約、運営付与、開発用切替、利用権確認失敗、契約終了、運営付与取消の各状態をテストする

- 4. オンライン利用権を運営付与できるようにする
  - 支払いを行わずオンラインモードを利用する対象者だけが、設定画面からFirebase Authへ新規登録またはログインできる導線を用意する
  - 対象者が運営へ提示するFirebase Auth UIDを設定画面で確認・コピーできるようにする
  - Firebase Admin SDKを使用し、Firebase Auth UIDを指定して運営付与の登録、状態確認、取消を行う運営専用コマンドを作成する
  - 運営付与の有無はオンライン利用権の判定だけに使用するFirebase Custom Claimとして保持し、プロフィールなどのデータを含めない
  - 運営専用コマンドは管理権限を持つ環境だけで実行し、サービスアカウントの認証情報をリポジトリへ保存しない
  - アプリからCustom Claimを変更できないようにし、Firestoreへのアクセスでもオンライン利用権を検証する
  - 付与または取消後にIDトークンを強制更新し、利用モードを再判定できるようにする
  - 付与対象UID、操作種別、実行日時、実行者、結果を監査記録として残す
  - 対象者の登録・ログイン、UID確認、運営専用コマンドによる付与、アプリでの利用権再確認までを運営付与手順書へ記載する
  - 取消前の利用者への通知とFirestoreからSQLiteへの手動同期、運営専用コマンドによる取消、アプリでの無料オフライン移行確認までを運営付与手順書へ記載する
  - UIDの取り違え、未登録UID、重複付与、付与取消、トークン更新失敗、権限のない環境からの操作をテストする

- 5. 地図関連APIの利用可否を統一管理する
  - 地図機能の利用可否と利用できない理由を表す状態をApplication層に定義する
  - 無料オフラインモードでは、ネットワークへ接続できる場合も地図関連APIを無効にする
  - オンラインモードでは、ネットワーク状態、API設定、一時的なAPI障害から利用可否をInfrastructure層で判定する
  - Presentation層は個別にネットワークやAPI設定を確認せず、共通の地図機能状態だけを監視する
  - ドロワーの地図画面、旅行編集の訪問場所、旅程編集の場所選択、場所検索、周辺地点検索、現在地を利用する地図操作へ共通の利用可否判定を適用する
  - 地図機能が利用できない場合は操作を無効化し、理由と再利用可能になる条件を共通の表示で案内する
  - 保存済みの場所名、座標、旅行・旅程との関連は、地図機能が利用できない場合も削除せず文字情報として参照できるようにする
  - UI以外から地図関連サービスが呼ばれた場合も、利用不可状態を共通の例外として返す
  - 無料オフライン、オンライン、通信不能、API設定なし、API障害時の表示と操作制御をテストする

- 6. 既存データ構造を維持したAndroid内部SQLite DBを構築する
  - `group_members`の既存データに保存されている`orderIndex`をER図へ追記する
  - `orderIndex`の反映漏れ以外はER図のテーブル、項目、主キー、外部キー、関連を変更しない
  - Firestoreの既存Collection・フィールド構造を変更せず、ER図と現在のFirestore Mapperを基準にSQLiteスキーマを定義する
  - Context7で最新の公式ドキュメントを確認してからDriftと必要な関連パッケージを追加する
  - Android内部ストレージにSQLiteファイルを作成し、DBの初期化、終了、バージョン管理を行う
  - Driftのスキーママイグレーション方針とマイグレーションテストを整備する
  - 日時、真偽値、nullable項目を既存Entity・DTOと相互変換できる保存形式に統一する

- 7. SQLite用のデータアクセス実装を追加する
  - メンバー、メンバーイベント、招待のMapper、Repository、QueryServiceを実装する
  - グループ、グループメンバー、グループイベントのMapper、Repository、QueryServiceを実装する
  - 旅行、訪問場所、タスク、旅程項目のMapper、Repository、QueryServiceを実装する
  - DVCポイント契約、期間限定ポイント、利用履歴のMapper、Repository、QueryServiceを実装する
  - 複数の更新を原子的に保存できるSQLite用`WriteTransaction`を実装する
  - 既存の並び替え条件、関連データの組み立て、保存・更新・削除の振る舞いをFirestore実装と一致させる
  - Repository、QueryService、TransactionのFactoryからSQLite実装を生成できるようにする
  - 各SQLite実装について、保存、取得、更新、削除、並び替え、関連データ取得、ロールバックをテストする
  - DBを閉じて再度開いた場合もデータが保持されることをテストする

- 8. 利用モードに応じてデータアクセスと認証を切り替える
  - 無料オフラインモードでは、Repository、QueryService、TransactionのFactoryからSQLite実装を生成する
  - オンラインモードでは、既存のFirestore実装を生成する
  - 無料オフラインモードでは認証画面とAuthGuardを経由せずに利用開始し、オンラインモードでは既存のFirebase Auth実装を使用する
  - 無料オフラインモードで既存UseCaseの実行に現在のメンバー情報が必要な場合は、ユーザー登録やログインとして扱わない端末内データとして初期化する
  - ネットワーク状態によってデータソースを切り替えない
  - UseCase、Domain Entity、DTOは利用モードと具象データソースを意識しない構成を維持する
  - 無料オフラインモードの通常利用ではFirebase、Firestore、Crashlytics、NTP、Places SDKを初期化せず、オンライン利用権の登録・確認を明示的に開始した場合だけ必要な認証処理を初期化する
  - オンラインモードで通信できない場合の表示と再試行方法を定義する
  - 無料オフラインモードでアプリを新規起動・再起動し、全業務データをSQLiteだけで操作できることをテストする
  - オンラインモードで既存の認証・共有・Firestore保存機能が維持されることをテストする

- 9. 設定画面からデータを手動同期できるようにする
  - バックグラウンドでの自動同期や利用モード変更時の自動同期は行わない
  - 設定画面にデータ同期ボタンを配置し、ユーザーが明示的に実行した場合だけSQLiteとFirestoreの間で全データを転送する
  - 同期実行前にSQLiteからFirestore、FirestoreからSQLiteのどちらへ転送するかをユーザーが選択できるようにする
  - SQLiteからFirestoreへ同期する場合は、Firebase Authでのログインとオンライン利用権が必要であることを案内する
  - 同期先に既存データがある場合は、同期元の全データで置き換えることを確認してから実行し、データを自動マージしない
  - FirestoreからSQLiteへ同期したグループ共有データは、その時点の端末内コピーとなり以後は自動更新されないことを案内する
  - SQLiteからFirestoreへ同期する場合は、新しく登録またはログインしたFirebase Authユーザーに対応するメンバーを移行データの所有者として設定し、既存のグループ・メンバー関連を維持する
  - 同期元データの件数と関連を検証し、失敗した場合は同期元を変更せずエラー表示から再実行できるようにする
  - 同期の最終成功日時と結果を設定画面で確認できるようにする
  - オンラインから無料へ変更する場合は、事前にFirestoreからSQLiteへのデータ同期を実行するよう警告する
  - 警告後もデータ同期を強制せず、ユーザーが同期しないまま無料へ変更できるようにする
  - SQLiteからFirestore、FirestoreからSQLite、同期キャンセル、同期失敗、同期先データあり、共有グループありをテストする

- 10. Androidウィジェットのバックグラウンド実行を利用モード切替へ対応する
  - バックグラウンド更新と操作コールバックでも、アプリ本体と共通のUseCaseをInfrastructure層のバックグラウンド用Composition Rootから取得する
  - 無料オフラインモードではSQLite、オンラインモードではFirestoreのQueryServiceを共通UseCaseへ注入する
  - 無料オフラインモードでは、バックグラウンドisolateからSQLiteを安全に開閉する
  - 選択中の利用モードに合わせて定期更新のネットワーク接続条件を設定し直す
  - アプリ内の旅程更新後、手動データ同期後、利用モード変更後にウィジェットキャッシュを更新する
  - 無料オフライン、オンライン、利用モード変更後、端末再起動後、アプリ未起動の状態で保存済み旅程を表示・操作できることをテストする

- 11. 無料オフラインモードのデータ保護・バックアップ方針を確定する
  - パスポート番号などの機微情報を含むSQLite DBについて暗号化要否と鍵管理方法を決める
  - Android Auto Backupと端末間転送へSQLite DBを含めるか、端末外へ出さないかを決める
  - アプリ削除、データ消去、端末故障時のデータ消失を案内する
  - 必要に応じて暗号化したエクスポート・インポートによる手動バックアップを実装する

- 12. 無料オフラインモード、オンラインモード、手動データ同期を総合検証して仕様書を更新する
  - 無料オフラインモードでは、ネットワーク接続の有無にかかわらずSQLiteだけで全業務データを作成・取得・更新・削除できることを確認する
  - 無料オフラインモードでは、すべての地図関連操作が同じ基準で無効化されることを確認する
  - ストア契約または運営付与によるオンラインモードでは、既存のFirestore保存、認証、共有、招待、地図機能が利用できることを確認する
  - 設定画面から双方向のデータ同期を実行し、同期対象データと関連が維持されることを確認する
  - オンラインから無料へ変更するときに、事前のデータ同期を促す警告が表示され、同期を強制しないことを確認する
  - アプリ再起動、端末再起動、オンライン利用権確認失敗、手動データ同期失敗から復旧できることを確認する
  - Androidウィジェットが選択中の利用モードに対応したデータを表示・操作できることを確認する
  - 不要になった直接依存、初期化処理、設定、テストを削除する
  - 確定したユーザーストーリーを基準に、無料オフラインモード、オンライン利用権、利用可能機能、データ保存先、設定画面からの手動データ同期をユースケース図へ反映する
  - ER図、Firebase設定、環境設定、運営付与手順書の説明を実装結果と一致させる

## マップの表示

- 地図画面上で表示対象グループを切り替えられるようにする
  - ドロワーから地図を選択したときは、年表と同じように所属グループを読み込む
  - 所属グループが2件以上の場合はグループ選択画面を表示し、1件の場合は選択画面を省略してそのグループの地図を表示する
  - グループ選択画面で所属グループを1つ選ぶと、そのグループを表示対象として地図画面へ遷移する
  - グループの読み込み中、所属グループがない場合、読み込みに失敗した場合は、既存のグループ選択画面と同じ表示と再読み込み動線を使用する
  - 場所検索ボックスの直下左側に、選択中のグループ名と下向き矢印を表示したコンパクトなチップを置く
  - チップをタップすると、所属グループから表示対象を1つ選べるポップアップメニューを表示する
  - グループを選択すると、そのグループに属する場所のピンと、ピン詳細に表示する旅行だけに絞り込む
  - 表示対象の切り替え時に開いていたピン詳細を閉じ、選択後のピンだけを移動対象にする
  - 場所検索は表示対象グループによる絞り込みの対象外とし、選択中のグループにかかわらず利用できるようにする
  - グループ名が長い場合はチップの最大幅を制限し、省略記号付きで表示する
  - 選択したグループに場所がない場合も地図とグループ選択は操作可能な状態を保ち、ピンがないことを案内する
  - 所属グループが1件の場合の選択省略、2件以上の場合のグループ選択、選択後の地図表示、地図上での別グループへの切り替え、場所がないグループの表示をWidgetテストで確認する
