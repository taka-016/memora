## カレンダー

対象は[ユーザーストーリー23〜25](user_stories.md)とし、[ADR-004](adr.md#adr-004-グループの予定と個人の外部予定を分離して扱う)および[ER図](er_diagram.md)に沿って実装する。

以下の番号順に対応する。各段階で関連するテストを追加・実行し、保存・表示の整合性を確認してから次へ進む。モデルの説明は末尾の補足を参照する。

### 6. 本人のGoogleカレンダー連携（ストーリー25・オンラインのみ）

- Composition Rootでモード別に依存実装を選択し、オフラインでは連携の入口を利用不可にしてGoogleカレンダーのSDK初期化と通信を行わない
- Googleカレンダーの認証・読取処理と、本人単位の連携設定・表示対象カレンダーの保存処理を追加する。設定を他のメンバーが読み書きできないようにする
- 外部予定はグループの予定として保存・共有せず、Googleカレンダーへの作成・編集・削除や双方向同期を行わない
- 本人が表示対象のGoogleカレンダーを選択し、その予定をグループの予定と同じ日付に読み取り専用で重ねて表示する。連携元のカレンダー名を表示し、グループ切替後も本人の外部予定を表示する
- Googleカレンダーからの読取では、外部の繰り返し予定も個別回の変更・取消しを反映して表示する。外部予定の繰り返し設定は読み取り専用とする
- 再取得で外部の変更を反映し、取得失敗を表示して再認証・再試行できるようにする。外部予定の取得状態をグループの予定と分け、失敗時もグループの予定を表示する
- 連携解除で本人の連携設定・表示対象を解除し、外部予定の表示を終了する。Googleカレンダーの予定とグループの予定は削除しない
- 本人だけへの表示・設定アクセス、取得元の識別、グループ切替後の継続表示、再取得、取得失敗時のグループ予定表示、再認証・再試行、連携解除、オフラインでの初期化・通信の抑止をテストする

### 補足: カレンダー関連モデル（Googleカレンダー連携は実装予定）

[ユーザーストーリー23〜25](user_stories.md)と[ADR-004](adr.md#adr-004-グループの予定と個人の外部予定を分離して扱う)および繰り返し設定の追加要望に対応する設計を示す。[ER図](er_diagram.md)の`calendar_events`と`calendar_labels`は単発予定の保存基盤をFirestore・SQLiteへ実装済み。`calendar_events.recurrenceRule`・`timeZone`と個別回の上書きは実装済み。繰り返しの入力画面と個別回・系列の編集・削除は実装済み。`google_calendar_connections`・`google_calendar_selections`は実装予定。Firestore・SQLiteともに個別回の変更・取消しを`calendar_event_overrides`に保存する。現在の保存構造は[ER図の補足](er_diagram.md#図の補足)を参照。

| エンティティ | 役割 | 保存・公開範囲 |
| --- | --- | --- |
| `calendar_events` | グループに属する予定のタイトル・期間・終日区分・色ラベル・繰り返しルール | オンラインはFirestoreで所属メンバーに共有、オフラインはSQLiteで端末内のみ |
| `calendar_event_overrides` | 繰り返し予定の個別回の変更・取消し | 親の予定と同じ保存・公開範囲 |
| `calendar_labels` | 誰に関係する予定かを表すグループごとの名前と色 | 予定と同じ保存・公開範囲 |
| `google_calendar_connections` | 本人と連携先Googleアカウントの対応 | オンラインのみ、連携した本人だけが読み書き可能 |
| `google_calendar_selections` | 本人が表示対象として選択したGoogleカレンダーのID | オンラインのみ、連携した本人だけが読み書き可能 |

- `calendar_events`は日付単位の予定であり、年表セルのメモである既存の`group_events`・`member_events`とは別に管理する。
- 予定は必ず1つのグループと1つの色ラベルに属する。予定の`groupId`とラベルの`groupId`は一致させる。タイトルは空にできず、終了日時は開始日時より前にできない。終日・複数日の予定も開始と終了の組で表す。
- `calendar_events.recurrenceRule`は未設定なら単発予定、設定時はRFC 5545のRRULE形式で上記の繰り返し条件を表す。開始・終了日時は初回を表し、時刻付きの系列は`timeZone`にIANAタイムゾーンIDを保持する。終日予定の日時欄は日付として解釈し、端末のタイムゾーン変更で日付をずらさない。
- `calendar_event_overrides`は`eventId`と`originalStartDateTime`の組で一意とする。元の開始日時（終日は元の開始日）をキーにし、実際の日時を変更してもキーは変更しない。`isCancelled`が真ならその回を非表示にし、偽なら変更後のタイトル・期間・終日区分・色ラベルをすべて必須で保存する。取消し時はこれらの変更後の値を不要とする。
- 個別回の上書き情報は繰り返しルールを持つ親予定にのみ属し、親のグループ・タイムゾーンに従う。個別回の上書き情報のラベルも親と同じグループに限定する。親の削除・系列の分割・ルール変更では、個別回の上書き情報の参照整合性と適用範囲も合わせて維持する。
- 色ラベルの名前は特定のメンバーや「家族全員」などを表し、予定の登録者とは独立して指定する。共通ラベルも扱うため、ラベルと`members`の直接参照は必須にしない。ラベル変更・削除時も予定の参照整合性を維持する。
- Googleカレンダー連携の`memberId`は連携した本人を表す。グループへの外部キーを持たせず、グループ切替にかかわらず本人の設定を利用する。表示対象は`memberId`と`calendarId`の組で一意とし、連携解除時に連携設定と表示対象を削除する。
- 外部予定の本文・期間・連携元カレンダー名はGoogleカレンダーから取得して表示し、`calendar_events`へ保存しない。連携解除でもGoogleカレンダーとグループの予定は削除しない。認証情報の安全な保存方法は実装時に検討し、この業務モデルにはトークンや秘密情報を含めない。
- オフラインでは予定・繰り返しルール・個別回の上書き情報・色ラベルをバックアップ・復元の対象に含める。Googleカレンダー連携設定と表示対象はオフラインの保存・復元対象に含めない。
