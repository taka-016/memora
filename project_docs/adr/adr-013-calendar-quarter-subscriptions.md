# ADR-013: オンラインの予定の購読範囲と表示時の取消判定を定める

## ステータス

採用。[ADR-009](adr-009-calendar-month-subscription-cache.md)を置換する。

## 決定日

- 2026-11-21 購読範囲を決定
- 2026-11-23 カレンダー表示時の取消判定と共有キャッシュの方針を変更

## コンテキスト

表示月とその前後の期間を購読する方式では、隣の月の予定が表示済みでも、初めてその月へ移ると重複する範囲の購読を追加する。連続して多くの月を閲覧しても、単発予定の購読範囲を一定に保ち、受信済みの予定を使って表示を継続したい。複数の期間にまたがる繰り返し予定は同じ親予定のルールから展開できるため、月移動による親予定の重複取得を減らしたい。

繰り返し予定の親は、全期間の取消IDを `overrideIds` に持つ。取消IDには元の回の開始日時が含まれ、展開した個別回を表示から除外するために使える。期間別に取消レコードを取得する方式では、親予定の取得に加えて読み取りが発生し、表示に使える取消の範囲も別に管理する必要がある。

## 検討した選択肢

| 選択肢 | 判断 |
| --- | --- |
| 表示月を基準に前後の期間を購読する | 不採用。隣の月へ進むたびに購読期間が重なる |
| 暦月ごとに購読する | 不採用。購読を共有できる期間が短く、閲覧した月数に応じてクエリ本数が増える |
| 閲覧が進むたびに単一の購読範囲を広げる | 不採用。購読範囲が閲覧期間に応じて広がり、範囲変更時に既存範囲を含めて取得する |
| 単発予定と繰り返し予定の親をともに固定の3か月単位で購読する | 不採用。複数の期間に該当する繰り返し予定の親が購読ごとに重複する |
| 単発予定は固定の3か月単位、繰り返し予定の親はグループごとに全期間で購読する | 採用。単発予定の取得範囲を一定に保ち、繰り返し予定の親を月移動後も再利用できる |
| カレンダー表示時に対象期間の取消レコードを取得する | 不採用。親予定の取消IDから分かる元の回の開始日時を追加で読み取り、取得済み範囲の管理も必要になる |
| カレンダー表示時に親予定の取消IDを使う | 採用。親予定の受信時点で、その系列の全期間の取消を表示に反映できる |

## 決定事項

- オンラインのカレンダー画面では、1〜3月、4〜6月、7〜9月、10〜12月の固定期間ごとに単発予定を購読する。繰り返し予定の親は、未来に開始する予定も含め、グループごとに全期間を1本で購読する。
- 購読と受信済みデータは、グループ状態の生存期間中に保持する。同じ期間の別の月や受信済みの期間へ移動するときは、保持しているデータを使う。
- 期間の最初または最後の月では、隣の月を含む期間を先読みする。先読みの待機・失敗は表示中の月の読み込み状態に影響させず、対象期間を表示したときにその状態を反映する。
- 表示対象の予定は表示期間との重なりで選定する。繰り返し予定の親の終了境界には `recurrenceEndDateTime` を使う。
- オンラインのアプリのカレンダーとAndroidのカレンダー・日別予定ウィジェットでは、表示対象の単発予定と、親予定から展開した個別回を表示する。取消判定には親予定の `overrideIds` のみを使い、元の回の開始日時が一致する個別回を除外する。親予定を変更検知の単位とする方針は[ADR-008](adr-008-online-calendar-streams.md)を適用する。
- アプリとAndroidウィジェットの共有キャッシュは、単発予定を月単位、繰り返し予定の親と全期間の取消情報をグループ内の系列単位で保持する。系列の取消情報は、その親予定を取得した時点の全期間分として扱う。
- 系列の編集・保存など、取消レコード本体の確認や更新が必要な操作では、`calendar_event_overrides` を参照する。保存時には取得していない取消を維持し、編集開始時の期待バージョンを使う。親予定と取消レコードは[ADR-006](adr-006-atomic-aggregate-updates.md)に従い、同じ保存単位で更新する。
- 通知では、予定の終了境界に `recurrenceEndDateTime` を使い、取消レコードは対象の系列・グループと元の回の期間で絞って取得する。
- グループ状態の生存期間中にアプリが開始する購読は、明示的な再試行を除き、単発予定は各グループの3か月ごとに一度、繰り返し予定の親は各グループにつき一度とする。グループ状態の破棄に伴って購読とキャッシュを解放する。

## 決定理由

単発予定の購読を固定の3か月で共有すると、暦月単位より購読本数が少なく、隣接期間を先読みすることで境目を越えるときの待ち時間も減らせる。繰り返し予定の親の購読を全期間で共有すると、初回の取得対象は広がるが、月をまたいで同じ親予定を繰り返し取得せずに済む。

取消済みの個別回を表示から除外するには、元の回の開始日時で照合すれば足りる。親予定のルールと取消IDは同じ文書から受信できるため、表示時の追加の読み取りを省ける。系列を単位に保持することで、月ごとに異なる版の親予定や取消情報を組み合わせる必要もなくなる。

## 結果

- 境目の先読みでは、まだ開いていない期間の単発予定を取得し、繰り返し予定の親と取消情報は系列単位で再利用する。
- 閲覧が進むと単発予定の購読数と月別キャッシュは増える。繰り返し予定の親の購読本数は、閲覧した期間数に依存しない。
- カレンダー表示用の予定データの読み取り対象は、単発予定と繰り返し予定の親になる。初回には終了済みの親予定や未来に開始する親予定も取得する。親予定の受信データ量は取消IDの件数にも依存する。実際の読み取り課金は親予定の総数、単発予定の分布、SDKの再接続にも依存する。
