# ADR-014: Firestoreの保存先をトップレベルのコレクションに統一する

## ステータス

採用。

## 決定日

2026-11-24

## コンテキスト

Firestoreの既存データは、カレンダーの個別回、旅行の旅程やタスク、DVCの利用データも含め、トップレベルのコレクションに保存している。親子関係やグループとの関連はドキュメントのフィールドに記録する。買い物リストの試験実装ではグループのドキュメント配下に品物を保存し、同じアプリ内で保存場所の探し方と取得方法が分かれた。

## 検討した選択肢

| 選択肢 | 判断 |
| --- | --- |
| エンティティごとにトップレベルのコレクションを使い、関連をIDのフィールドで表す | 採用。既存データと同じ方法で参照・管理できる |
| 親ドキュメントの下にサブコレクションを置く | 不採用。エンティティによって保存場所の探し方と取得方法が分かれる |

## 決定事項

- Firestoreの保存先はトップレベルのコレクションに限る。サブコレクションは禁止し、例外を設けない。
- 親子関係やグループとの関連は、親のIDやグループIDをドキュメントのフィールドに持たせて表す。親やグループで範囲を絞る取得では、そのフィールドを条件に使う。
- この方針はアプリ、Firestoreルール、運用スクリプトに適用する。

## 決定理由

保存場所がエンティティごとのトップレベルに揃うと、親ドキュメントをたどらずにFirebaseコンソールで対象データを見つけられる。関連をフィールドで表すことで、既存のデータと同じ方法で取得条件やルールを確認できる。

## 結果

親やグループとの関連を持つデータには、対応するIDのフィールドが必要になる。関連IDによる絞り込みと並び替えを組み合わせる場合は、クエリに応じて複合インデックスを定義する。
