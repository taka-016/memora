# ADR-009: 表示済みの月のキャッシュと購読を維持する

## ステータス

採用

## 決定日

2026-11-15

## コンテキスト

[ADR-008](adr-008-online-calendar-streams.md)で採用したオンラインの予定監視は、月移動時に購読を切り替えていた。取得済みの月へ戻るたびに初回受信が必要となり、予定の表示待ちと再取得が発生する。予定の追加・変更、特に直近以外の月の変更は、月の閲覧・往復に比べて少ない利用を想定する。

既存の月単位の取得範囲には前後の表示に必要な期間も含まれ、隣接月の範囲が重なる。同じ単発予定や繰り返し系列が複数の購読対象に含まれる場合がある。

## 検討した選択肢

| 選択肢 | 判断 |
| --- | --- |
| 表示中の月だけを購読する | 不採用。月を往復するたびに再購読が必要になる |
| 月別のキャッシュを残し、表示中の月だけを購読する | 不採用。即時表示は可能だが、戻る際の再購読は残る |
| 閲覧済みの月のキャッシュと購読を維持する | 採用。月の往復で追加取得せず、非表示月の変更も反映できる |
| 全期間を一括で購読する | 不採用。未閲覧の期間も初回取得・監視の対象となる |

## 決定事項

- オンラインのグループ予定は、閲覧した月ごとに受信済みデータと購読をメモリ上に保持し、月移動によって既存の購読を解除しない。表示済みの月へ戻る際は再購読せず、保持したデータを即時表示する。
- 非表示月への変更受信は該当月のキャッシュへ反映し、表示中の別の月の予定や取得状態を上書きしない。取得成功・待機・失敗は月ごとに扱い、空の取得成功と未取得を区別する。
- 保持範囲はカレンダーのグループ状態の生存期間とする。画面の購読終了やグループの選択解除などで状態が破棄された場合、保持していた全月の購読とキャッシュを解放する。永続的な月別キャッシュは追加しない。
- 明示的な再読み込みでは表示中の月の購読を再開し、他の月の購読は維持する。色ラベルとグループ情報の再読み込みは既存の方式を維持する。
- 更新時は既存の変更差分処理を維持し、無関係な予定や月の全件再取得は行わない。更新された予定が複数の取得範囲に含まれる場合、各購読で変更を受け取る。繰り返し系列の変更では、その系列の各取得範囲内の取消情報を再取得する。
- 通信の回帰検証は、エミュレータを使わず、アプリが開始する購読回数と追加取得回数を対象にする。10か月の初回表示後の往復による追加購読は0回とし、更新時の再購読・無関係な予定の取消情報の追加取得も0回を目標とする。SDKによる再接続、実際の転送バイト数、Firestoreの課金量はこの検証の保証対象外とする。
- オフライン、端末カレンダー、通知、Androidウィジェットの取得方式、およびADR-005〜008の保存時の排他・取得時点の混在許容は変更しない。

## 決定理由

表示済みの月への往復で購読と初回取得を繰り返すより、更新頻度の低い月も購読を保持する方が、想定する利用では表示待ちと不要な再取得を減らせる。全期間の購読を避け、閲覧した範囲だけを保持することで、未閲覧期間の初回取得を増やさない。

非表示月の受信や失敗を月ごとに保持することで、月を戻した際に最新の受信内容と復旧に必要な状態を表示できる。追加の整合性検証や保存処理の変更は必要としない。

## 結果

- 表示済みの月への往復では通信を開始せず、受信済みの予定を即時表示できる。
- 閲覧した月の数に応じてメモリ使用量と購読数が増える。非表示月の変更も受信し、取得範囲が重なる予定の更新では複数の購読で処理する。総通信量は更新頻度や再接続にも依存し、削減を一律には保証しない。
- 通信回数の目標をテストで固定し、月の往復や差分更新による不要な取得の再導入を検出できる。
- 画面を開き直した場合やグループを再選択した場合は初回取得が必要となる。
