# ADR-010: 起動時の認証トークン更新をFirebase SDKの通常管理に任せる

## ステータス

採用（実装は未完了）

## 決定日

2026-11-15

## コンテキスト

オンライン版では、起動時に有効期限が残っている認証トークンも強制更新し、その通信完了を待ってから本人メンバーを確認している。ウィジェットから予定追加を開く場合もこの待機が発生する。

Firebase SDKは有効なトークンの再利用と期限に応じた更新を扱える。所属権限はFirestoreの`account_permissions`で管理しており、所属変更を反映するために起動のたびにトークンを強制更新する必要はない。

## 検討した選択肢

| 選択肢 | 判断 |
| --- | --- |
| 起動のたびに認証トークンを強制更新する | 不採用。アカウントの無効化などを起動時に検知できるが、有効なトークンがあっても通信待ちが発生する |
| 有効なトークンを再利用し、期限に応じた更新をFirebase SDKに任せる | 採用。無効化などの検知の遅れを許容し、起動時の強制更新による待機を減らす |

## 決定事項

- オンライン版の起動時認証ではトークンを毎回強制更新せず、有効なトークンの再利用と期限に応じた更新をFirebase SDKの通常のトークン管理に任せる。
- アカウントの無効化・削除や認証情報の失効を、起動時に必ず検知することは保証しない。次のトークン更新まで検知が遅れることを許容する。
- 認証状態の監視と本人メンバーの確認は維持する。Firestoreへのアクセス権限は引き続きセキュリティルールで判定し、キャッシュ上のログイン状態だけをアクセス許可の根拠としない。
- 通信不要の起動や、期限切れトークンでのアクセス成功を保証するものではない。必要なトークン更新や本人メンバーの確認には引き続き通信・待機が発生し得る。

## 決定理由

アカウントの無効化などを毎回起動時に確認することより、有効なトークンを再利用して入力開始までの待ち時間を減らすことを優先する。追加の独自トークン管理を設けず、Firebase SDKの標準機能を利用する。

FirebaseのIDトークンの有効期間は通常1時間であり、強制更新を外すと既存トークンの有効期間中に無効化などの検知が遅れる場合がある。この遅れを許容する判断とし、即時検知のための追加の仕組みは設けない。

## 結果

- 有効なトークンがある場合、起動時の強制更新に伴う通信と待機を削減できる。
- アカウントの無効化などが、次のトークン更新までアプリに反映されない場合がある。
- 認証状態の監視・本人メンバーの確認と、その失敗・再試行の扱いは維持する。
