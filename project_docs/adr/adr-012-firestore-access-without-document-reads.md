# ADR-012: Firestoreルールの評価で追加のドキュメントを読み取らない

## ステータス

採用

## 決定日

2026-11-20

## コンテキスト

オンライン版では、Firestoreルールがグループへの所属と管理者権限を判定するために、複数のドキュメントを読み取っていた。旅行や予定の参照、保存、購読にルール評価用の読み取りが加わり、所属の変更時には同じグループIDの一覧を複数のドキュメントに保存していた。公開の要件は未確定で、当面は読み取り回数と実装の複雑さを抑える。

## 検討した選択肢

| 選択肢 | 判断 |
| --- | --- |
| Firestoreルールでグループへの所属・管理者権限を検証する | 不採用。評価中の読み取りと所属・管理者情報の重複が必要になる |
| アカウントごとに記録を分ける | 不採用。別アカウントのメンバーによる招待・共同編集を維持する |
| メール確認済みのログインと操作対象の検証に絞る | 採用。ルール評価で追加のドキュメントを読み取る必要がなくなる |
| バックエンドでグループごとの権限を検証する | 保留。公開やアクセス制御の要件が決まった段階で検討する |

## 決定事項

- オンライン版のFirestoreルールは、アプリのデータへのアクセスをメール確認済みのログインユーザーに許可する。利用可否設定の個別取得は未ログインでも許可し、クライアントからの書き込みは引き続き拒否する。
- 操作対象のデータだけで確認できるバージョン、参照IDの変更制限、色の形式、ラベルの使用件数などの検証は残す。親子の一括保存や削除時の退避はアプリのトランザクションで維持する。
- グループへの所属と管理者設定は `group_members` を参照し、本人のメンバー情報は `members.accountId` で取得する。メンバー文書に複製したグループID一覧、`account_permissions`、`member_invitation_claims` を廃止する。
- アプリの通常画面では所属グループの表示と、グループの所有者・管理者の操作を維持する。招待によるメンバーとアカウントの紐づけ、および所属メンバーによる記録の共同編集を引き続き提供する。

## 決定理由

ルール内の別ドキュメント参照をなくすと、ルール評価用の追加読み取りをなくせる。現在の運用では、グループごとのサーバー側アクセス制御よりも、読み取り回数と所属情報を同期する実装の削減を優先する。

## 結果

- メール確認済みの利用者は、Firestoreに直接アクセスすると、所属していないグループや一人だけのグループの記録も読み書きできる。招待コードの照合、親子の同時更新、削除時の退避など、操作対象以外の情報が必要な検証は、直接アクセスに対するサーバー側の保証から外れる。
- アプリによるグループ一覧の取得、購読、トランザクションには引き続きFirestoreの読み取りが発生する。本番の読み取り回数は利用状況に依存する。
- 廃止する情報に依存するアプリの旧版は、ルール変更後に本人や所属グループを取得できなくなる。旧データの整理は[専用手順](../../scripts/firebase/remove_firestore_authorization_data.md)を参照する。
- [ADR-006](adr-006-atomic-aggregate-updates.md)の集約単位で競合を検出する方針はアプリの保存処理で維持する。Security Rulesの親参照による検証は本ADRで置き換える。
