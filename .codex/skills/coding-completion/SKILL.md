# Coding Completion

コード変更を完了する前に、このリポジトリで求められる締め手順を揃える。

## 基本方針

- ユーザーが`todo`更新の省略を明示した場合は、その指示を優先する。
- 併用する専門スキルが対象作業の`todo`更新を不要と明示している場合は、その専門スキルを優先する。
- このスキルは、`coding`で必要なコード変更とコミットが完了していることを前提に使う。
- 検証や最終確認で修正が必要になった場合は完了作業を中断し、`coding`に戻って修正とコミットを完了してからやり直す。
- ユーザーがpush、PR作成の省略を明示していない限り、完了条件にはそれらを含める。

## 手順

1. `git status`と直近のコミットを確認し、`coding`で必要なコミットが完了していることを確認する。未コミットの差分がある場合は`coding`に戻る。
2. ドキュメントのみの差分の場合は`./check.sh`を実行しない。コード、設定、生成物、テストに差分がある場合は`./check.sh`を実行し、エラーが残っていないことに加えて、テスト出力に予期しないExceptionログやエラーログが出ていないことを確認してから完了作業に進む。エラーまたは予期しないExceptionログが出た場合は`coding`に戻る。`./check.sh`の実行によって発生した差分はこのタイミングでコミットする。
3. ユーザーまたは併用する専門スキルによる`todo`更新の除外がなければ、作業に対応する`docs/todo.md`の項目を削除する。
4. ユーザーまたは併用する専門スキルによる`todo`更新の除外がなければ、今回作業指示された`docs/todo.md`の項目が残っていないことを確認する。
5. プルリクエストの作成、既存プルリクエストへのpush・本文等の更新、レビューコメントへの返信を行う前に、サブエージェントへ独立レビューを依頼する。コード変更のない返信も対象とする。
   - 新規PRでは比較元ブランチからの差分全体、既存PRでは今回の変更差分と返信・更新内容の根拠となるPR差分・関連経路を対象にする。作業目的と比較元を伝え、`AGENTS.md`の「レビュー方針」「アーキテクチャ」「コーディング規約」に沿って確認してもらう。サブエージェントにはファイルを変更させず、実際の発生条件と影響、対象箇所を日本語で報告してもらう。
   - 主担当は指摘の妥当性と修正による複雑性を判断する。修正が必要なら`coding`に戻り、修正・検証・コミット後に本手順をやり直し、変更後の差分もサブエージェントに再レビューしてもらう。
   - 同時実行枠の不足などでサブエージェントを一時的に作成できない場合は、枠が空いてから作成を再試行する。サブエージェント機能が利用できない場合、再試行してもサブエージェントを作成できない場合、または妥当な指摘が未解決の場合は、予定していたPRの作成・更新・返信を行わず状況を報告する。
6. ユーザーがpushやプルリクエスト作成の省略を指示していない場合、pushし、プルリクエストが未作成なら作成する。既存PRへの更新・返信は手順5の独立レビューを終えてから行う。
7. `todo`更新を行った場合、プルリクエストの説明には完了(削除)した作業対応項目を記載する。

## 実行上の注意

- 検証が失敗している状態で完了扱いにしない。
- `./check.sh`が成功していても、テスト中に予期しないExceptionログやエラーログが出ている状態で完了扱いにしない。
- `coding-completion`内で新たな修正差分を抱えたまま完了させない。差分調整が必要なら`coding`へ戻す。
